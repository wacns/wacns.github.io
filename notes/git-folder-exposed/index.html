My static site was serving its own .git folder

Oct 23, 2026 · 3 min read

The day after pointing my domain at a Cloudflare Worker, I opened Cloudflare’s security analytics to see where a few hundred requests had come from. I hadn’t shared the site with anyone yet.

Most of it was the usual background noise of the internet: bots asking for /.env, /aws.env, /appsettings.Production.json, /.svn/wc.db and dozens of other places secrets tend to leak from. Nearly all of them got a 404. Then one line stood out:

GET /.git/HEAD → 200

What was exposed

I requested it myself. /.git/HEAD returned the hash of my latest commit, and /.git/config returned the repository’s remote URL. That’s enough for off-the-shelf tools to walk the .git folder and rebuild the entire repository, history included.

Why it happened

The site is a plain HTML repository with no build step. Cloudflare’s Git integration clones the repo and runs npx wrangler deploy. With no config file in the repo, Wrangler detected a static site and generated its own config with the assets directory set to ., meaning the whole checkout.

Nothing in that path skips dot-folders, so .git was uploaded and served like any other file, along with tooling files such as my editor notes.

How bad was it?

In my case, not very: the repository is already public on GitHub, so nothing leaked that wasn’t already visible. But the same setup with a private repo would publish the full source and every secret that was ever committed to its history, to anyone who asks.

The fix

Workers static assets support an .assetsignore file in the assets directory, using the same syntax as .gitignore. Anything listed there is never uploaded:

.assetsignore
# Files the Worker must never serve
.git
.git/**
.claude
.claude/**
CLAUDE.md
wrangler.jsonc
worker.js
.gitignore
.assetsignore

After the next deploy, /.git/HEAD, /.git/config and the tooling files all return 404, while every real page and asset still loads.

What I took from it

  • Check what your deploy actually uploads, not what you think it uploads. Auto-generated configs are convenient and generous.
  • Scanners find you within hours, not weeks. New TLS certificates are published in public logs, and bots watch them.
  • A 200 on a path you never created is an alert. Skimming the status codes in your analytics once in a while is cheap insurance.
