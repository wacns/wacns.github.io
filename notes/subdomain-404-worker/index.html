A 404 page for every subdomain that doesn’t exist

Oct 24, 2026 · 4 min read

Type a random subdomain of most personal domains, say hello.example.com, and the browser says the site can’t be reached. There’s no DNS record, so the request never gets anywhere.

I wanted those visits to land on my own 404 page instead. The catch: a few subdomains on my domain already run real apps through a Cloudflare Tunnel, and those had to stay exactly as they were.

The four pieces

  1. A wildcard DNS record. A proxied AAAA record for *.example.com pointing to 100::, Cloudflare’s placeholder for “handled at the edge”. Explicit records always win over a wildcard, so existing subdomains keep resolving where they did.
  2. A wildcard Worker route. *.example.com/* sends every subdomain request to the site’s Worker.
  3. An exclusion route per app. Routes like app.example.com/* with no Worker attached. The most specific route wins, so app traffic never touches my Worker at all.
  4. A hostname check in the Worker. The main domain gets the site, anything else gets the 404 page.

The Worker

The site is otherwise static, so the Worker is tiny. It runs before the static assets so it can decide by hostname:

worker.js
const SITE_HOSTS = new Set(["example.com", "www.example.com"]);
const APP_HOSTS  = new Set(["app.example.com", "api.example.com"]);

export default {
  async fetch(request, env) {
    const host = new URL(request.url).hostname;

    // The real site
    if (SITE_HOSTS.has(host)) return env.ASSETS.fetch(request);

    // Safety net: apps are excluded by route, but pass them through just in case
    if (APP_HOSTS.has(host)) return fetch(request);

    // Everything else: the 404 page, with a real 404 status
    const page = await env.ASSETS.fetch(new URL("/404.html", request.url));
    return new Response(page.body, { status: 404, headers: page.headers });
  },
};

And the matching bits of the Wrangler config. run_worker_first makes the script see every request, and not_found_handling covers missing paths on the main domain:

wrangler.jsonc
{
  "main": "worker.js",
  "assets": {
    "directory": ".",
    "binding": "ASSETS",
    "run_worker_first": true,
    "not_found_handling": "404-page"
  }
}

HTTPS everywhere, while I was there

With every subdomain now answering, I also turned on Cloudflare’s Always Use HTTPS and sent an HSTS header with includeSubDomains, so browsers stop trying plain HTTP anywhere on the domain.

Testing it

  • http://random-test-123.example.com/hello redirected to HTTPS and showed the 404 page with a 404 status.
  • Each app subdomain still went straight to its own login screen.
  • The main site and www were unchanged.

The one gotcha

The catch-all is greedy. When I add a new app subdomain, it gets the 404 page until I add its exclusion route.

That’s why the Worker keeps a list of app hostnames as a safety net, and why “add the exclusion route” is now part of my checklist for every new subdomain.
